BTCT ("Been There, Conquered That") is a real-time, multi-user pentest note-taking app: collaborative markdown pages, nmap import, team command capture and shared screenshot assets with non-destructive crop and redaction. Runtime is **Bun** everywhere; the whole thing ships as one Docker image. It is built to run on a small box (1 to 2 GB of RAM, 1 to 2 cores), so a feature that costs steady memory or CPU has to earn it.

## Writing style for generated prose

**Never use em dashes (`—`) in anything you write.** Not in docs, not in commit messages, not in code comments, not in PR descriptions, not in the blog. An em dash is almost always a decision that got skipped, so make the decision instead:

| Instead of | Use |
|---|---|
| `Notes went in Word — five operators, five documents` | a full stop: `Notes went in Word. Five operators, five documents` |
| `- **Term** — definition` | a colon: `- **Term**: definition` |
| `read — and, when allowed, edit — the workspace` | parentheses: `read (and, when allowed, edit) the workspace` |
| `it renders offline — no network calls` | a comma: `it renders offline, with no network calls` |
| a table cell containing only `—` | `none` |

En dashes are fine in real ranges (`H1–H3`, `3–32`) and inside literal UI strings you are quoting. Run `grep -c '—' <file>` before you call a doc change done. It should be `0` everywhere; the table just above is the only deliberate exception in this repo, because it has to quote the character to name it.

Related habits worth keeping: skip the ban-list words (seamless, leverage, robust, comprehensive, delve, unlock, supercharge), do not bold every feature noun, and vary sentence length instead of writing everything at 20 words.

## Commands

Client (repo root; run scripts with `bun run`):
- `bun install`: install client deps.
- `bun run dev`: Vite dev server (hot reload). Needs the server running separately (below).
- `bun run build`: **typecheck + build**: `tsc -b && vite build`. This is the canonical "does it compile" check.
- `bun run lint`: ESLint.
- `bun run test`: Vitest (all suites, in `src/test/`).
  - Single file: `bun run test -- src/test/pane-layout.test.ts`
  - By name: `bun run test -- -t "moveTab"`
- `bun run seed`: seed a demo workspace (`vite-node src/db/seed.ts`).

Server (in `server/`, plain `.mjs`, no build step; Bun runs it directly):
- `cd server && bun install`
- `cd server && bun run dev`: server with `--watch`. Requires env: `AUTH_SECRET`, and set `YPERSISTENCE=./data/yjs` or Yjs rooms are memory-only. For a full local dev pair, run this + `bun run dev` in two terminals (client falls back to same-origin; set `VITE_API_URL`/`VITE_WS_URL` only for a split host).

Deploy / run the real app (single container, serves client + API + Yjs on one port):
- `docker compose up -d --build`: build image and (re)launch. Requires `AUTH_SECRET` in `.env`. Health: `curl 127.0.0.1:8080/healthz` (use `127.0.0.1`, not `localhost`, on a Windows/WSL2 Docker host: `wslrelay.exe` accepts `[::1]:8080` but cannot forward IPv6, so `localhost` hangs; see README "Running on Windows").
- Image asset blobs land in `ASSETS_DIR` (default: `assets/` beside `DB_PATH` → `/data/assets`), on the same `btct-data` volume as SQLite + Yjs, so existing backups cover them. Page history twins land in `HISTORY_DIR` (default: `history/` beside `DB_PATH` → `/data/history`) and are a backup category of their own (`history`).
- Backups: **Admin panel → Backups** (`server/backup.mjs`) writes one folder per run to `BACKUP_DIR` (`/backups`, bind-mounted from `./backups`). Restore with the container stopped: `docker compose stop btct && docker compose run --rm btct bun server/restore.mjs /backups/<name> --yes && docker compose start btct`.
- After editing a `server/*.mjs` file, note the **Dockerfile copies server files individually**. A new server file must be added to the `COPY server/...` lines or it won't be in the image. A pure server module that `src/test` imports needs a `.d.mts` beside it; those are copied into the client-build stage too (`COPY server/*.d.mts`) because `bun run build` typechecks the tests.

> The `.mjs` server is not covered by `tsc`. Sanity-check syntax with `bun build ./server/<file>.mjs --target=bun --external '<npm deps>' --outfile /tmp/x.js`.

## Architecture: the big picture

### There is no traditional database. Data lives in Yjs CRDT documents.

The "DB" is a set of **Yjs documents** synced over WebSockets and cached in IndexedDB. Every data change flows:

```
UI → repo/store action → write a Y.Map / Y.Text (inside doc.transact)
   → y-websocket broadcasts to server + peers → each client's Y observer fires
   → shared-bindings re-derives Zustand state (debounced) → React re-renders
```

`src/db/database.ts` looks like Dexie (`get/add/put/update/where().equals()`) but is a shim over the shared Y.Maps, **not** a local database. A write there propagates to *every connected user*.

### Two-tier Yjs design

| | Shared doc (`src/realtime/shared-doc.ts`) | Per-page doc (`src/realtime/yjs-providers.ts`) |
|---|---|---|
| Room | `btct-shared` | the page's `id` |
| Holds | all entity records (one `Y.Map` per table) + one `texts` `Y.Map` of `Y.Text`s | one page body as a `prosemirror` `Y.XmlFragment` |
| Edited by | repos/stores | Milkdown collab plugin |

- **Records** = plain JSON in a per-table `Y.Map` keyed by `id` (last-writer-wins). Tables: `workspaces, pages, changeLogs, pageSnapshots, nmapScans, nmapMachines, typstAssets, assetFolders, commandLogs`. One more map, `settingsPublic`, is a **server-written** mirror of the public settings (the admin theme policy under key `theme`, stamped `themeUpdatedAt`, and the blur-strength defaults under key `blur`, stamped `blurUpdatedAt`); clients only read it.
- **Collaborative text fields** (page title/slug, workspace name, nmap-scan name, nmap hostname) are authoritative as a `Y.Text` in the `texts` map, keyed `<entity>:<id>:<field>`. A `mirrorTextsToRecords` observer copies each `Y.Text` back into the JSON record so everything else reads plain JSON.
- **Page bodies never go in the shared doc**: they're per-page docs. Their version history lives on the server (`server/history.mjs`, see below); the old `pageSnapshots` map is read once for import and no longer written.

### Client layers
- `src/db/*-repo.ts`: one repo per entity: CRUD + queries, pre-seeds `Y.Text`s on create, cascades deletes.
- `src/stores/app-store.ts`: the Zustand store (workspaces, pages, tabs, split-pane layout, nmap, assets, command log, change log). Mutating actions call repos **and** `log()` a change-log entry.
- `src/stores/shared-bindings.ts`: `bindSharedSubscriptions()` maps each table's `Y.Map.observe` to a microtask-debounced store reload.
- `src/lib/theme.ts` + `src/stores/theme-store.ts`: accent and note-heading theming by CSS-variable rewrite (never an editor rebuild). Precedence is one pure function, `resolveEffectiveHeadings` (admin hardlock → the user's own prefs, as a whole once customised → admin defaults → inherit), applied from `App.tsx`. The admin policy is seeded by `GET /api/settings` and then followed live through `settingsPublic.theme`; the store drops payloads older than the `themeUpdatedAt` it already holds. Per-user prefs (`theme` next to `codeAccent`/`keybinds`/`follow`) are validated by `resolveThemePrefs` on the client and the matching validator in `server/index.mjs`. The same store carries the workspace blur-strength defaults (seeded and mirrored the same way under `settingsPublic.blur`); `resolveBlurStrengthPolicy` in `src/lib/editor-prefs.ts` (user pref, else admin default, else `DEFAULT_BLUR_STRENGTH`) decides what strength a new redaction region starts with. A new region defaults to `DEFAULT_BLUR_STYLE`/`DEFAULT_BLUR_STRENGTH` from `blur-math.ts`: pixelate at 0.4, which the dialog prints as 40%. Those are a **different thing** from the `effectiveStyle`/`effectiveStrength` fallbacks (gaussian at 1) and must stay so, because those two exist to render records written before the fields did; moving them would silently re-render every redaction anyone has saved. `server/index.mjs` mirrors the strength constant, since it has no build step and cannot import it.
- `src/themes/`: one Operations look, in `operations.css`, scoped under `html[data-ui-theme="operations"]`. Solid **neutral-grey** panels (every surface token is zero-saturation on purpose), native system fonts, compact borders, no backdrop blur or continuous decorative animation. The status colours and the account accent are the only hues; do not reintroduce a tinted grey. Both dark and light palettes remain; user accent and editor colours still apply. Never reset transforms on a wildcard: report SVGs require them.
- `src/lib/editor-keybinds.ts`: editor plugins that apply settings without a rebuild (invariant #3) plus the code-block language defaults: `codeBlockShellDefault` (schema default) **and** `codeFenceInputRule`, which replaces commonmark's own ``` input rule (`PageEditor` calls `crepe.editor.remove(createCodeBlockInputRule)` before `.use()`-ing ours) because that rule stores the captured language verbatim and ProseMirror input rules are first-match-wins. Re-adding the preset rule silently turns bare fences back into plain-text blocks. `userKeybindsPlugin` also owns the `Ctrl/⌘+Shift+0..8` turn-into shortcuts (via `lib/turn-into.ts`), routes the `link` action to the inline link editor, and re-applies the last-used highlight colour. Every shell/PowerShell alias folds to one of those two keys.

### Note images are shared assets (`src/lib/asset-image.ts` + `note-image-paste.ts`)
Pasting/dropping an image into a note does NOT embed bytes: `noteImagePastePlugin` (capture-phase `paste`/`drop` listeners on the editor DOM, because Milkdown's clipboard plugin owns the `handlePaste` prop and would consume the event first) uploads it via `addTypstAsset` and inserts an `asset_image` node that references the asset by id. So a note image appears in the Assets Manager and shares its non-destructive crop/blur pipeline. The `asset_image` node is a custom `$node` + plain-DOM `$view` (never Crepe's Vue image view): the view renders `resolveAssetBytes(asset)` (crop + blur applied) as a blob URL and subscribes to the store so a blur committed in the editor updates the note live; `data-asset-id` is mirrored onto the DOM for the right-click menu. Editing opens `ImageEditorDialog` via the `editingAssetId` store flag and the app-level `AssetImageEditor` host; the right-click menu and the `blurImage` keybind (`Mod-Shift-b`) both open it. The original upload is never overwritten, so a blur is always removable. Markdown round-trips as `![](asset:<id>)`. `asset_image` is in image-resize's `IMAGE_TYPES`, so the drag-resize handle works on it too. The read-only history viewer (`HistoryView`) includes `asset_image` in its schema (`crepe.editor.use(assetImageSchema)`) and gives it a `nodeViews` entry that resolves the bytes, so a version you're about to restore shows the actual picture (a placeholder once retention has pruned it). `noteImageCleanupPlugin` (an `appendTransaction`) deletes the shared asset when its `asset_image` node leaves the doc and no other node in the doc still references it (permanent: undo restores the node but not the bytes). A `shortcuts` TabKind renders `src/components/help/ShortcutsView.tsx`, a grouped cheat-sheet whose editor rows read the account's live keybinds.

### Command log ingest (`server/cmdlog.mjs` + `cmdlog-agent/`)
A standalone Python 3 agent (`cmdlog-agent/`, stdlib-only) runs on each operator's Kali box: a bash/zsh shell hook captures whitelisted commands to a per-PID spool file, and a daemon correlates start/exit, redacts secrets, and batch-POSTs them to `POST /api/cmdlog/events` (static bearer ingest token). Storage is **split on purpose**:
- **SQLite `command_logs`** (`db.mjs`) is the durable, unbounded archive; rows are **upserted by the agent-generated `id`** so a start event and its later exit/duration completion merge, and a replayed batch is idempotent. Read with filters over `GET /api/cmdlog/query`.
- **The shared doc's `commandLogs` map** (written via `appendCommandLogs` in `yjs-data.mjs`) is a **bounded live window** (~500/workspace, pruned oldest-first) so the Command Log tab updates live without polling. It has **no Y.Text fields**, all LWW JSON (like `typstAssets`), so invariant #1 doesn't apply.
- The client view (`src/components/cmdlog/CommandLogView.tsx`, a `cmdlog` TabKind) **seeds from REST on mount, then follows the CRDT**, sidestepping the cold-doc problem where server CRDT writes are lost if `YPERSISTENCE` is unset and no browser is connected. Pure filter/CSV logic is in `src/lib/cmdlog-filter.ts` (tested).

### Retired features (`src/export/retired.ts`)
Web recon, the attack-narrative graph canvas, findings, the attack timeline, attack chains, the in-app Claude assistant and the Typst report tab were removed. Their UI, routes, repos, store slices, subscriptions and `TABLE_NAMES` entries are gone, so a running client pays nothing for them.

What is **not** gone is the data. The old Y.Maps (`siteMaps`, `siteMapNodes`, `siteMapEdges`, `graphs`, `graphNodes`, `graphEdges`, `attackChains`, `timelineEvents`) still exist inside the shared doc of any workspace that had them, and `src/export/retired.ts` reads and writes them directly off `getSharedDoc()`, so:
- a workspace ZIP exported by this build still carries every one of those records, under the same top-level filenames older builds wrote, and
- importing such a ZIP puts them back, with ids remapped exactly like live records.

Adding a table to `TABLES` in that file is all it takes to retire another feature the same way. Full server backups copy the whole doc, so they preserve these records regardless. There is deliberately **no prune**: dropping the maps would destroy the only copy of an old engagement's graph.

### Data retention (`server/retention.mjs`)
Admin-configurable, OFF by default (`settings.retention_days = 0` = keep forever). When set to N days, a `createJob` (scheduler.mjs) run on boot + every 6h deletes `page_versions` older than N days and permanently removes assets that were RETIRED (soft-deleted) more than N days ago (bytes under `ASSETS_DIR`, the `assets` SQLite row, and the shared-doc `typstAssets` record, read via `doc.getMap('typstAssets')` since the server's `TABLE_NAMES` omits it). Last run is persisted in `settings.retention_last_run`, so an overdue prune fires right after boot (same pattern as backups). Note-image deletion RETIRES the asset (`deletedAt` on the record, hidden from the Assets Manager) rather than hard-deleting, so history keeps showing the image until the window prunes it; the Assets Manager's own delete button still hard-deletes. Admin routes `/api/retention/*` (config, run, history-range) are admin-only. `startRetentionScheduler()` is called at boot in `index.mjs`.

### Backups (`server/backup.mjs`, `data-export.mjs`, `restore.mjs`, `scheduler.mjs`, `backup-format.mjs`)
The server snapshots itself into `BACKUP_DIR`, one **directory per run** (`btct-backup-YYYYMMDD-HHMMSS/` with `manifest.json`, `sqlite/data.sqlite.gz`, `yjs/<room>.yupdate.gz`, `assets/<id>`), built under a `.tmp` name and renamed after the manifest lands. Reads go through `data-export.mjs` only: SQLite via `VACUUM INTO`, each Yjs room as one update (from the relay's in-memory doc when open, else y-leveldb), assets copied by id. **Never copy the live SQLite file or LevelDB directory** (invariant #12). `scheduler.mjs` is a single-timeout job (no overlap, persisted last run so an overdue backup fires right after boot); config lives in `settings` (`backup_*` keys) and the admin UI saves it per change. Status and run-now also accept a static `backup_token` (same static-bearer pattern as the command-log ingest token) for host schedulers. Nothing is pruned automatically by decision; the UI lists and deletes runs. `restore.mjs` is a CLI for a stopped server: verifies hashes, refuses if LevelDB is locked, moves old data to `pre-restore-<stamp>/`, rebuilds rooms with `storeUpdate`. `backup-format.mjs` and `scheduler.mjs` are pure and unit-tested from `src/test/` through `.d.mts` declarations.

### Page version history (`server/history.mjs`, `server/history-diff.mjs`, `src/components/history/`)
Google Docs-style, and the reason the server keeps a second copy of every page. Live page docs are GC-on, so deleted text vanishes once every client has seen the deletion; `trackPageDoc` (called from the websocket `connection` handler for every room but `btct-shared`) keeps a **GC-off twin** fed by the relay doc's `update` events and flushed atomically to `HISTORY_DIR/<pageId>.ydoc`. A **version** is `Y.snapshot(twin)` in the `page_versions` SQLite table (`trigger` auto/named/restore/import, name, creator, `changed_by`); imports from the legacy `pageSnapshots` map carry full `state` instead. Policy: auto 2 minutes after the last update, every 10 minutes of continuous editing, and on room close, skipped when the body did not change; nothing is thinned. Attribution: clients call `attachUserMapping` (`Y.PermanentUserData`, `users` map, description = account id) after sync; `changedUsersBetween` (pure, `Y` injected, tested in `src/test/page-history.test.ts`) counts only items inside the `prosemirror` fragment. Client: `page-history-api.ts` (routes, twin download), `HistoryView.tsx` (TabKind `history`; own read-only ProseMirror with the editor's schema plus `ychange` from `lib/history-schema.ts`, built once from a headless Crepe that must stay alive because node `toDOM`s read its ctx; y-prosemirror's snapshot renderer does the per-user colouring), `page-snapshots.ts` (`restoreFromState`: one ProseMirror transaction through the registered page editor, `lib/active-editor.ts`, else a fragment clone), `PageHistoryPanel.tsx` (launcher + named save). Backups copy the twins as the `history` category.

### Server (`server/`): intentionally thin
Bun `node:http` + `ws`. It does **auth + static hosting + a Yjs relay** and knows almost nothing about what a page or a scan means. `bun:sqlite` (`db.mjs`) stores only `users`, `settings`, `page_versions`, `command_logs`, `assets` (blob inventory: size/mime, never meaning). Routing is a flat `if (method && url)` chain in `index.mjs` using `authFromHeader`/`requireAdmin`/`readJsonBody`/`sendJson`. Auth = PBKDF2 passwords + HMAC-signed tokens (`auth.mjs`), 7-day TTL.

## Critical invariants (read before touching the data layer)

These are non-obvious and easy to break; full list in README "Conventions & invariants".

1. **Pre-seed `Y.Text`s in every repo `create()`** (`getOrInitYText(textKey(...))`) or two clients race and orphan the text. A *new* collaborative field means touching all four: `TEXT_FIELDS_BY_ENTITY` + `TEXT_FIELD_TO_TABLE` (`shared-doc.ts`), the repo `create()`, and the UI (`useYTextInput`).
2. **Read the JSON record, not the `Y.Text`.** The mirror keeps them in sync; only the editor/input layer touches `texts`.
3. **Never rebuild the editor to apply settings.** Keybinds and code accent flow through module-level refs + CSS vars specifically so the Yjs collab binding survives; remounting drops live cursors/edits.
3b. **Programmatic Y.Text rewrites use `replaceYTextContent`** (minimal delta). A clear-and-reinsert destroys remote cursors and can't merge with a concurrent edit.
3c. **A drag writes to the DOM, once per animation frame, and commits to React state only on pointer-up.** Pane resizing does it for the reason in #3 (a mid-drag re-render can remount an editor and drop its collab binding); the crop window's blur and pan gestures do it for cost: a pointer fires up to 1000 events a second against a 60 Hz display, and a `setState` per sample measured 3.2 ms of render work per event with a dozen blur regions on screen. Never put a `backdrop-filter` on an element a drag resizes either, or the compositor re-blurs the whole backdrop per sample. Width math + persistence live in `src/lib/pane-resize.ts` (pure, tested); `src/test/viewport-drag.test.tsx` guards the crop window by counting commits, not milliseconds.
4. **Keep the server dumb about domain data.** Four deliberate exceptions: `backup.mjs` + `data-export.mjs` (move bytes: a `VACUUM INTO` snapshot, per-room Yjs updates, asset copies; they know room names, never meaning), `history.mjs` (keeps a per-page twin doc and its versions), `assets.mjs` (stores opaque blobs; knows size + mime, never meaning), `cmdlog.mjs` (ingests externally-produced command records into SQLite + the CRDT; validates and stores, knows nothing about what a command means). `yjs-data.mjs` is the only module that reaches into the shared doc, and it is now down to what those three need: `listWorkspaces`, `appendCommandLogs`, the two `settingsPublic` mirrors and the asset-retention pair. Nothing there writes a `Y.Text`; if you add something that does, it must set BOTH the `Y.Text` and the JSON record.
4b. **Never put binary content in the shared doc.** Upload it and reference it by id (see the note-images section). Page versions are server-side too (`page_versions` + `HISTORY_DIR`); the legacy `pageSnapshots` map is import-only.
4c. **Live page docs are GC-on, the history twins are GC-off, and twin files never pass through y-leveldb.** `server/history.mjs` feeds each twin from the relay doc's `update` events and writes it atomically to `HISTORY_DIR/<pageId>.ydoc`; a version is a `Y.snapshot` of that twin, so deleting the twin file makes every diffable version of that page unrenderable (imports keep their own full state). Attribution only works while clients call `attachUserMapping` after sync and only counts items inside the `prosemirror` fragment (`server/history-diff.mjs`). Restores go through the live editor when the page is open (`restoreFromState`), never a clear-and-reinsert on a doc someone is typing in.
5. **DB migrations must be idempotent.** Guard every `ALTER TABLE` with a `PRAGMA table_info` column check (see `db.mjs`).
6. **Load `yjs` on the server via the same CJS require as y-websocket** (`require('yjs')`, not `import`), or you get two Yjs instances and `Y.Text` writes silently fail to integrate.
7. Deletes cascade and are logged with a full snapshot (restorable). Highlight marks and page bodies are intentionally not in the change log.
8. **Subscribe to the store with a selector, never bare `useAppStore()`.** A selectorless call re-renders on every `set()` (each sync event, each debounced save). Use per-field selectors or `useShallow` for multi-field reads.
9. **Password hashing is async and must stay off the event loop.** `hashPassword`/`verifyPassword` (`server/auth.mjs`) use `crypto.pbkdf2` on the libuv threadpool because the process also runs the Yjs relay; a synchronous hash freezes every editor. Login is throttled per username+IP (`server/index.mjs`).
13. **A skin must not create stacking contexts on the rails or the content column** (`[data-ui="sidebar"]`, `[data-ui="main"]`: no `backdrop-filter`, `filter`, `transform`, `isolation`, `z-index`). Dialogs opened from the rails now render through `src/components/ui/Portal.tsx` into `<body>` (Chrome painted the History tab's composited scrollers over a fixed overlay left inside a rail, in both themes), but dialogs inside the content column still rely on this rule; a stacking context traps them behind later siblings. The Operations skin uses opaque surfaces and no mount animation. **A skin must never reset `transform` on `*`** (not even under `prefers-reduced-motion`): reset only the transforms the skin itself sets (`src/test/glass-theme.test.ts` guards this). And because unlayered rules beat Tailwind's hover utilities, every surface a skin restyles needs its own `:hover`.
12. **Never copy the live SQLite file or LevelDB directory.** WAL journals and open LevelDB logs make raw copies corrupt. Go through `server/data-export.mjs`, or stop the container.
11. **Never put secrets in `settingsPublic`.** It is mirrored to every connected client; only the public theme and blur-default policies belong there.
10. **Batch CRDT/SQLite writes.** Wrap multi-record Yjs writes in one `sharedTransact` and SQLite batches in one `db.transaction` (`upsertCommandLogBatch`); `PRAGMA synchronous = NORMAL` pairs with WAL so a batch is one commit, not one fsync per row.

14. **No native browser dialogs, and native controls follow the theme.** `window.confirm`/`prompt`/`alert` paint outside the skin; use `src/components/ui/ConfirmDialog.tsx` (a portal sheet, with an optional input for prompts) or an inline notice. `index.css` declares `color-scheme` on `:root`/`.dark` so select popups, date/colour pickers and spinners render dark, and restyles `select` (own chevron, `appearance: none`) and the accent of range/checkbox/date inputs; keep those rules when touching form styling. Audit record: [docs/ui-audit-2026-08-28.md](docs/ui-audit-2026-08-28.md).
15. **Tabs reconcile against the shared doc; the active pane is always a live leaf.** `reconcileTabs()` prunes tabs whose entity is gone (after the pages/nmapScans reloads and local deletes, no-op until synced); every layout change goes through `reconcileActive()`; `moveTab` removes, adds, then collapses, in that order.
16. **Bulk record creation outside the repos must call `seedMissingYTexts(getSharedDoc())`** (seed, zip import): a record without its `Y.Text` drops inline edits until a reload. `database.ts` deletes drop the record's texts.

## Performance
The current implementation and measurements are recorded in [docs/lightweight-redesign-2026-09-06.md](docs/lightweight-redesign-2026-09-06.md).

Generated `dist/` is not versioned. `bun run build` recreates it locally; the Docker client stage always builds from source. Do not commit generated bundles or restore stale recon assets.

The Operations branch uses lazy editor, export, image-editing and account panels. `code-accent.ts` and `editor-keybind-registry.ts` let the shell update preferences without loading editor code. Removing the graph canvas took `@xyflow/react`, `@dagrejs/dagre`, `html-to-image` and `date-fns` out of the client; removing the assistant took `@anthropic-ai/sdk`, `@modelcontextprotocol/sdk` and `zod` out of the server; and removing the Typst tab took the three `@myriaddreamin/typst*` packages, which were 29 MB of WebAssembly on their own.

Per-page contexts are retained by open page/history tabs and short-lived operation leases. Closing the last tab releases its socket and document after editor cleanup and a committed IndexedDB snapshot. Never delete the persistent cache during teardown. A storage failure keeps the context alive and retries on a later tab change. Exports await the source documents and work in batches of four. `page-context-lifetime.test.ts` covers close/reopen, offline content, leases and failed storage. Selection-only editor transactions reuse decorations through a WeakMap keyed by the immutable document. The UTC clock updates by minute and pauses while hidden; history polling does the same and never overlaps requests. Vite groups icons into one chunk.

Local preview: `docker compose --env-file .env.preview -f docker-compose.preview.yml up -d --build`, bound to `127.0.0.1:8081`, with separate named data and backup volumes, 1 GB memory and two CPUs. That limit is the target machine, not a safety margin: measurements against it live in [docs/lightweight-redesign-2026-09-06.md](docs/lightweight-redesign-2026-09-06.md). `.env.preview` contains generated preview-only credentials and is ignored. Stop with the same compose flags followed by `stop`; this preserves preview data.

Full CPU/memory audit and the fixes applied: [docs/perf-audit-2026-08-19.md](docs/perf-audit-2026-08-19.md); the 2026-08-28 multi-agent pass (54 confirmed findings, what was fixed, what is still open with a recommended fix): [docs/perf-bug-audit-2026-08-28.md](docs/perf-bug-audit-2026-08-28.md). Static assets are precompressed at build time (the Dockerfile gzips `dist/`) and `tryServeStatic` serves the `.gz` sibling plus an mtime+size ETag; only `/assets/*` (hashed names) is `immutable`, everything else is `no-cache`, and `.wasm` must stay in the MIME table (streaming instantiate). Heavy tab views are `lazy()` imports in `SplitContainer`; the interface uses system fonts; the logo ships as small PNG/ICO variants, never the source PNG.
